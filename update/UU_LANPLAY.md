# UU 加速器虚拟局域网使用说明

UU 加速器的「虚拟局域网」（Lanplay）会给同一房间内的玩家分配同网段私有 IP，
效果等同你们坐在同一个路由器下。对本项目有两个用处。

## 前提

1. 双方都开 UU 加速器，**进同一个虚拟局域网房间**
2. 双方都能在「网络连接」里看到一块叫 **`UU Lanplay`** 的网卡
3. 记下各自的 IP（启动器会自动帮你找）

启动器 → 「③ AI 之间对话」→ **网卡**那一行会显示，例如：

```
172.19.163.2  (UU Lanplay, 局域网)
```

如果是房主，卡片里会直接写：

```
把这句发给对方 → 172.19.163.2:7150
```

## 一、游戏联机（解决端口问题）

游戏本身走 UDP 7140，正常情况下只有房主需要能被访问。用 UU 虚拟局域网后：

| 之前的问题 | UU 虚拟局域网下 |
|---|---|
| 要开路由器 UDP 7140 端口转发 | **不需要**，同一虚拟局域网直接通 |
| CGNAT / 双 NAT 无法穿透 | **不需要**，虚拟局域网自己处理 |
| 要配 Tailscale / ZeroTier | **不需要**，UU 已经做了 |

操作：

1. 房主开游戏 → MULTIPLAYER → Direct → HOST A GAME → OPEN THE LOBBY
2. 点 **COPY JOIN ADDRESS**
3. **把地址里的公网 IP 换成你的 UU IP**，即把
   `公网IP:7140#CODE` 改成 `172.19.163.2:7140#CODE`
   （`#CODE` 那串加入码必须原样保留）
4. 发给对方，对方 JOIN A GAME 粘贴进去

> 如果 Windows 防火墙拦了，仍需放行一次 UDP 7140（私有网络）：
> ```
> netsh advfirewall firewall add rule name="RE CVX co-op" dir=in action=allow protocol=UDP localport=7140
> ```

## 二、AI 之间对话

我们的通道走 TCP 7150，独立于游戏联机。

**房主**：
1. 启动器 → 「③ AI 之间对话」→ 勾选启用
2. 角色选「我是房主」
3. 网卡选 `172.19.163.2 (UU Lanplay)`
4. 保存配置 → 启动游戏和助手

**加入方**：
1. 启动器 → 勾选启用
2. 角色选「我是加入方」
3. 对方地址填房主发来的 `172.19.163.2`（只要 IP，端口默认 7150）
4. 保存配置 → 启动

两边都启动后，右键小鲸鱼 → 「问问对面 AI 什么情况」就能验证是否连通。

同样，防火墙第一次可能弹窗，允许「专用网络」即可。

## 排查

**网卡下拉里没有 `UU Lanplay`**

- UU 没启动，或没进房间
- 点启动器上的「保存配置」不会刷新网卡列表 —— **关掉启动器重开**
- 确认 UU 用的是「虚拟局域网」而不是普通加速模式

**提示"端口 7150 绑定失败"**

- 有另一个助手实例在跑，先全退出
- 或者端口被别的程序占了，把端口改成 7151（双方要改一样）

**显示"已连接"但 AI 不说话**

这是正常的 —— 我们不是闲聊模式。只在以下情况才发消息：
- 换房间
- 捡到东西
- 血量骤降
- 你手动右键「问问对面」

想立刻验证，就右键问一句。

**连接一直失败**

1. 双方 IP 都对吗？（`ping 对方的UU IP` 试试）
2. 双方在同一个 UU 房间吗？
3. 防火墙放行了 TCP 7150 吗？
4. 试试把房主那边的「网卡」改成 `0.0.0.0`（监听全部网卡）

## 为什么不能自动发现

一台机器上常有多块网卡：

```
172.19.163.2   UU Lanplay          ← 要走这个
192.168.124.3  以太网               ← 物理网卡
192.168.163.1  VMware VMnet8       ← 虚拟机虚拟网卡
192.168.246.1  VMware VMnet1       ← 虚拟机虚拟网卡
```

广播式自动发现会同时发到这几块上，经常发到 VMware 的假网卡里然后石沉大海。
所以启动器让你**明确选一块**，默认会猜 `UU Lanplay`（识别网卡名里的
`uu` / `tailscale` / `zerotier` / `virtual` 等关键词）。
